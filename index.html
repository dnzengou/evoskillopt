Quickstart Manual

Five steps from clone to a live evolutionary skill loop.

STEP 01

Clone the repository

Get the integration core and the reference SKILL.md manifests onto your machine.

git clone https://github.com/dnzengou/evoskillopt.git
STEP 02

Install dependencies

Python 3.11+ recommended. All optimization primitives live in the core package.

cd evoskillopt && pip install -r requirements.txt
STEP 03

Pick a SKILL.md manifest

Start with v1.0 Core for a vanilla evolutionary loop, or jump to v2.0 for Matrix + Circuit Breaker.

evolvedskillopt/EVOLVED_SKILL.md
STEP 04

Run the optimization loop

Seed a population, let GRPO mutate it, let Q-Gate validate, let the Breaker watch.

python evolved_skill_opt_v1.1.0_full_implementation.py
STEP 05

Wire EvoMetaClaw (optional)

Capture live sessions and feed them back as training signal during idle windows.

# enable meta_claw: true in config
STEP 06

Observe & pin

Track replicator scores, niche spread, and Q-Gate pass rate. Pin the winner.

evoskillopt pin --generation=latest

Lexicon

Core terms used across EvoSkillOpt manifests, in plain language.

Skill Genome CORE

A single candidate prompt / tool-config / policy, treated as a point in the optimization population.

Replicator Dynamics EGT

Evolutionary game-theoretic update rule where better-scoring genomes gain share of the population each generation.

GRPO MUTATION

Group-Relative Policy Optimization. Scores candidate mutations relative to their peer group instead of a fixed baseline.

Q-Gate SAFETY

A quality gate run before a mutation is admitted into the live population; failing candidates are discarded.

Niche Clustering DIVERSITY

Groups similar genomes so selection pressure is applied inside clusters — preserves diversity against mode collapse.

Matrix-Thinking REASONING

A 4D multi-perspective analysis step applied before any mutation, exploring parallel framings of the same decision.

Circuit Breaker SAFETY

Runtime guard that halts evolution on stagnation, diversity collapse, or excessive recursion depth.

EvoMetaClaw META

Conversational proxy layer that captures live sessions and converts them into offline training signal during idle windows.

Idle Window SCHEDULING

A low-traffic period during which expensive evolutionary runs are allowed to execute without impacting live latency.

Subagent ORCH

A specialist agent instance spawned by the orchestrator for a bounded task; evaluated on coordination efficiency.

Active Hub DEPLOY

The current production tier of the platform — the fused infrastructure running the full optimization loop.

Pin OPS

Freezing a specific genome or generation as the serving version while evolution continues in the background.

Frequently Asked Questions

Short answers to the questions we get the most.

What is EvoSkillOpt in one sentence?
An open-source framework that treats agent skills as a population and evolves them safely in production using replicator dynamics, GRPO, Q-Gate validation, and Circuit Breakers.
Do I need my own model to use it?
No. EvoSkillOpt is model-agnostic. The reference manifests run on Claude, GPT-4, Gemini, Mistral, and local models. You bring the inference, EvoSkillOpt evolves what you send into it.
How is this different from just prompt optimization?
Prompt optimization tunes one prompt. EvoSkillOpt maintains an evolving population of skill genomes, selects between them with replicator dynamics, and gates every change with safety checks. Prompts are one dimension of a skill, not the whole thing.
Is it safe to run evolution against live users?
That is the point of the Q-Gate + Circuit Breaker pair. Candidates are validated offline before admission, recursion depth is bounded (default max_depth=2), and the breaker halts evolution on stagnation or diversity collapse. You can also pin a generation and run evolution purely in shadow.
What does EvoMetaClaw actually capture?
Conversational traces from live sessions, with PII handled by your own policy. It converts those traces into training signal for the next evolution run, scheduled to execute in idle windows so it does not touch serving latency.
Can I use only part of the stack?
Yes. Each version from v1.0 to v3.1 is a standalone SKILL.md manifest. Start with v1.0 for a pure evolutionary loop and add Matrix-Thinking, orchestration, or meta-learning when you need them.
